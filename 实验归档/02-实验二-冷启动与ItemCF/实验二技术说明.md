# 实验二技术说明：Popular、Cold Start 与 ItemCF

## 冷启动策略

冷启动接口面向没有评分、收藏等行为的新账号。系统先读取该账号的真实评分与收藏历史：若没有行为且未选择类型偏好，则使用 `popular_non_personalized` 作为显式热门回退；用户选择电影目录中存在的类型后，则将类型偏好传给 `cold_start`，优先推荐与所选类型匹配的影片，并结合数据中的平滑口碑得分排序。类型来自真实电影目录，最多允许 5 项；接口会拒绝目录外类型、过多类型，以及将 `genres` 参数用于非冷启动算法的请求。响应中的 `recall_sources` 用于区分热门回退与类型召回，避免把非个性化结果误称为个性化推荐。

本次真实账号 `account_id=1`（`exp2_cold_98ebeda865`）经评分与收藏接口确认均为 0 条。默认请求返回 10 条，模型为 `cold-start-genres-v1`，来源为热门回退；选择 `Action` 后仍返回 10 条，来源为类型偏好，且与默认榜单的电影 ID 顺序及集合均有差异。完整接口结果摘要见 [实验二验收API结果.md](实验二验收API结果.md)。

## ItemCF 原理与实现

ItemCF 读取实验一指定的真实历史匿名用户评分记录，并将评分不低于 4.0 的电影视为正向种子；收藏是独立的二元正向信号，不转换成虚构评分。对种子电影与候选电影，算法基于训练交互数据中的正向用户集合计算物品余弦相似度：

`sim(i,j) = |U_i ∩ U_j| / sqrt(|U_i| × |U_j|)`

共同交互用户少于 2 的邻居不参与，单个种子最多保留 200 个近邻。候选电影得分按用户种子权重（评分种子使用 `rating - 3`，收藏作为独立信号）累加相似度贡献；随后过滤该用户已评分或已收藏的电影，并按得分排序。候选不足时热门结果用于补足，并标记为 `popular_fallback`。本次 `ml14` 与 `ml55` 各返回 10 条唯一结果，两个 Top10 的 ID 交集为 0；`ml14` 有 15 条历史评分，`ml55` 有 19 条，推荐均未命中各自已评分集合。
